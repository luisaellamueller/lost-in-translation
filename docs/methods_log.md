## Current research question

How do German translations generated by an open-weight LLM from official French
interpellation texts differ in sentiment from the corresponding official German
texts, and do automated differences correspond to differences identified by
German-speaking readers?

We compare two German versions of each document. French is the designated input;
we have not established that it is the original submission language. We therefore
study differences relative to an official reference, not verified fidelity to an
original author's wording.

## Decisions and reasons

| Decision | Reason | Consequence or limitation |
| --- | --- | --- |
| Make the paired translation experiment the core | The feedback identified historical changes in topics, translation practice, and classifier behaviour as confounds | No longitudinal analysis or causal claim about historical machine translation adoption |
| Use French input and German output | Both researchers speak German and English, so both can independently evaluate German outputs | Neither can independently establish fidelity to the French input |
| Compare sentiment in German only | This removes direct cross-language score comparison from the primary outcome | German classifier accuracy and sensitivity to paraphrasing still require validation |
| Use the official German text as the reference baseline | It provides an existing institutional version for the same document | It is not a sentiment gold standard and its human/machine production history is unknown |
| Do not infer source language from member language or canton | Such metadata does not establish the language of a particular submission | Some cases may effectively involve back-translation; do not call all official German versions translations from French |
| Start with five examples | Test the full process cheaply before expanding | These are development examples, not a representative evaluation sample |
| Target roughly 30 documents for the MVP | Keep data inspection and human evaluation feasible before the deadline | Final size and sampling rule are not fixed; avoid population-level claims from a convenience sample |
| Use an open-weight local LLM | Avoid paid API access as a requirement for regeneration and make the model identifiable | Reproduction still requires suitable hardware, software, a model download, and compliance with its licence |
| Select Meta Llama 3.1 8B Instruct | The user preferred a recognisable general-purpose model; its model card explicitly supports French and German | This is a choice of one specific model, not evidence that it is the best translator or representative of all LLMs |
| Plan to use 4-bit quantisation | Reduce weight memory on the user's M4 Pro with 24 GB unified memory | Quantisation can affect outputs; the selected Q4_K_M conversion and its checksum are recorded below; translation quality is not yet tested |
| Keep code small and type-hinted | Make every step understandable and easy to explain | No extra abstractions or dependencies without a concrete need and user agreement |

## Planned evaluation (not yet executed)

- Freeze one translation prompt and decoding configuration before the evaluation
  sample. Give the LLM only the French input, not the official German reference.
- Check completion and coverage before accepting generated translations. Record
  failures; do not silently drop difficult cases or select favourable outputs.
- Choose and document text segmentation/aggregation without silently truncating
  inputs. Apply the same scoring procedure to both German versions.
- Retain all three sentiment probabilities. A proposed scalar is
  `S = P(positive) - P(negative)`. It is a model-derived index, not calibrated
  emotional intensity.
- For each document, report `S(LLM) - S(official)` and its absolute value.
  Positive signed differences mean more positive model scores, not necessarily
  weaker criticism or better translation quality.
- Create a small independently annotated German validation set using explicit
  sentiment guidelines before showing classifier predictions.
- Report classifier agreement with human labels and, where supported by the
  sample, per-class performance. Report class counts and small-sample limits.
- Have both researchers assess blinded German pairs, including both large-score
  differences and a random subset. Record annotator agreement before adjudication.
  Extremes alone cannot estimate how often meaningful changes occur.
- Distinguish sentiment changes, modality changes, harmless paraphrases,
  classifier errors, and extraction issues. Modality is not identical to sentiment.
- Keep development examples separate from the final evaluation when practical;
  document any overlap and all decisions informed by the pilot.

### First task: independently annotate the five German pilot texts

Template: `data/processed/pilot_annotation.csv` (UTF-8 with BOM for Excel).
Each researcher saves a separate copy and completes it without discussing
individual ratings or seeing classifier predictions. These five documents are
for developing instructions, not a sufficient validation set or final evaluation.
Read the complete reference_de text; use the title only as context.

Fill the following fields:

- annotator: your name or a consistent identifier.
- sentiment: positive, neutral, negative, mixed, or unclear. Judge the author's
  expressed evaluation. Mixed means both positive and negative evaluation are
  present; do not average them into neutral. Uncertainty is not neutral.
- criticism_strength: 0, 1, 2, 3, or unclear. Judge the strongest criticism the
  author expresses or endorses in this document, not the severity of its topic.
  This is an ordinal pilot rubric, not an established validated scale.
  - 0: no discernible criticism; factual description or genuine information request.
  - 1: mild criticism; restrained concern, reservation, or a suggestion of improvement.
  - 2: clear criticism; explicit negative evaluation, allegation of failure, or blame.
  - 3: emphatic criticism; forceful condemnation, emphatic blame, or strongly
    intensified negative evaluation.
  - unclear: the author's stance cannot reasonably be determined.
- criticism_target: who or what is criticised (for example an institution,
  policy, or practice). Leave blank if there is no criticism.
- criticism_evidence: copy the exact phrase(s) supporting your strength rating.
  Include enough context for negation, qualification, and attribution. Leave
  blank for strength 0 and explain ambiguous cases in notes.
- praise_evidence: copy any wording expressing praise or positive evaluation;
  leave blank if none is present.
- notes: explain uncertainty, several targets, reported speech, or disagreement
  between overall sentiment and the strongest critical passage.

Do not infer criticism merely from words describing harm, risk, or illness.
Questions can imply criticism, but not every parliamentary question does.
Distinguish an allegation reported from someone else from one endorsed by the
speaker. Read negation, hedging, and context rather than counting negative words.

After both copies are complete, retain the original independent ratings, compare
judgments, and revise unclear instructions. Do not replace the random pilot just
because its criticism is weak. Five examples can reveal issues but cannot
establish classifier accuracy or corpus-wide sentiment prevalence.

## Implemented sentiment scorer (12 November 2026)

`scripts/score_sentiment.py` reads a JSON object with a records list containing
`document_id`, `reference_de`, and `translation_de`. It uses the cached German
sentiment BERT at revision b1177ff59e305c966836ba2825d3dc2efc53f125 on CPU.
Preprocessing follows the author's implementation:
https://github.com/oliverguhr/german-sentiment-lib/blob/master/germansentiment/sentimentmodel.py
It removes URLs/mentions, spells digits individually, filters characters and
lowercases model input only. The saved source text is not modified.

Long texts are split into non-overlapping token chunks within the model limit;
no tokens are silently truncated. Probabilities are averaged with content-token
weights. This provisional aggregation may split sentences and dilute local
criticism; it needs pilot validation before the final experiment. Chunk scores
and lengths remain available for inspection. The scorer saves all probabilities,
the derived label, P(positive)-P(negative), signed translation-minus-reference
differences, and absolute differences. These are not validated intensity scores.
No new dependencies or model training were introduced. Human annotation can
proceed independently; no pilot predictions were shown to annotators.
